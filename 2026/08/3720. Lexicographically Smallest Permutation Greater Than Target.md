### Problem Statement:

You are given two strings `s` and `target`, both having length `n`, consisting of lowercase English letters.

Return the **lexicographically smallest permutation** of `s` that is **strictly** greater than `target`. If no permutation of `s` is lexicographically strictly greater than `target`, return an empty string.

A string `a` is **lexicographically strictly greater **than a string `b` (of the same length) if in the first position where `a` and `b` differ, string `a` has a letter that appears later in the alphabet than the corresponding letter in `b`.

> [!example]- Example 1
> **Input:** s = "abc", target = "bba"
>
> **Output:** "bca"
>
> **Explanation:**
>
> 	- The permutations of `s` (in lexicographical order) are `"abc"`, `"acb"`, `"bac"`, `"bca"`, `"cab"`, and `"cba"`.
>
> 	- The lexicographically smallest permutation that is strictly greater than `target` is `"bca"`.

> [!example]- Example 2
> **Input:** s = "leet", target = "code"
>
> **Output:** "eelt"
>
> **Explanation:**
>
> 	- The permutations of `s` (in lexicographical order) are `"eelt"`, `"eetl"`, `"elet"`, `"elte"`, `"etel"`, `"etle"`, `"leet"`, `"lete"`, `"ltee"`, `"teel"`, `"tele"`, and `"tlee"`.
>
> 	- The lexicographically smallest permutation that is strictly greater than `target` is `"eelt"`.

> [!example]- Example 3
> **Input:** s = "baba", target = "bbaa"
>
> **Output:** ""
>
> **Explanation:**
>
> 	- The permutations of `s` (in lexicographical order) are `"aabb"`, `"abab"`, `"abba"`, `"baab"`, `"baba"`, and `"bbaa"`.
>
> 	- None of them is lexicographically strictly greater than `target`. Therefore, the answer is `""`.

> [!warning]- Constraints
> - `1 <= s.length == target.length <= 300`
>
> 	- `s` and `target` consist of only lowercase English letters.

### Hints:

> [!success]- Hint 1
> Maintain frequency counts of `s`.

> [!success]- Hint 2
> Walk left-to-right; if equal to `target[i]` is possible, take it and continue.

> [!success]- Hint 3
> If not, try the smallest letter strictly greater than `target[i]`.

> [!success]- Hint 4
> If neither, backtrack left to the most recent index where you matched `target` and try to bump there.

### Submission:

> [!example]+ Submission
> | Runtime | Memory | Time | Space |
> |---|---|---|---|
> | `27 ms` | `19.3 MB` | `O(n²)` | `O(1)` |
>
> ```python
> class Solution:
>     def lexGreaterPermutation(self, s: str, target: str) -> str:
>         freq = Counter(s)
>         ans, first, breaks = "", False, []                    # + breaks
>
>         def up(c):                                            # + smallest available char > c
>             for v in range(ord(c) + 1, ord("z") + 1):
>                 if freq[chr(v)]: return chr(v)
>             return ""
>
>         def backoff():                                        # + retreat to last viable break
>             if not breaks: return ""
>             k = breaks[-1]
>             for ch in ans[k:]: freq[ch] += 1
>             i = up(target[k]); freq[i] -= 1
>             return ans[:k] + i + "".join(ch * n for ch, n in sorted(freq.items()) if n)
>
>         for c in target:
>             i = c if not first else "a"
>             while freq[i] == 0:
>                 v = ord(i) + 1
>                 if v > ord("z"): return backoff()             # was: return ""
>                 else: i = chr(v)
>             if not first and up(c): breaks.append(len(ans))   # + record break point
>             first = True if first else (i != c)
>             freq[i] -= 1
>             ans += i
>         return backoff() if ans == target else ans            # was: "" if ans == target
> ```

> [!success]- Reasoning
> 1. Count frequency of each character in s to track available choices
> 2. Greedily build result left-to-right: match target[i] when possible, record "break points" where a higher char exists
> 3. Track whether we've diverged from target; once we do, greedily pick smallest available chars
> 4. If forced to backtrack (no chars available), return to most recent break point and pick the smallest char strictly greater than target[k]
> 5. Fill remaining positions with sorted order of available characters
>
> **Key insight:** Greedy left-to-right with strategic backtracking to the nearest position where we can choose a larger character.
