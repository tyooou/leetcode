### Problem Statement:

Given a 2D `grid` of size `m x n` and an integer `k`. You need to shift the `grid` `k` times.

In one shift operation:

	- Element at `grid[i][j]` moves to `grid[i][j + 1]`.

	- Element at `grid[i][n - 1]` moves to `grid[i + 1][0]`.

	- Element at `grid[m - 1][n - 1]` moves to `grid[0][0]`.

Return the _2D grid_ after applying shift operation `k` times.

> [!example]- Example 1
> **Input:**
>
> ```python
> `grid` = [[1,2,3],[4,5,6],[7,8,9]], k = 1
> ```
>
> **Output:**
>
> ```python
> [[9,1,2],[3,4,5],[6,7,8]]
> ```

> [!example]- Example 2
> **Input:**
>
> ```python
> `grid` = [[3,8,1,9],[19,7,2,5],[4,6,11,10],[12,0,21,13]], k = 4
> ```
>
> **Output:**
>
> ```python
> [[12,0,21,13],[3,8,1,9],[19,7,2,5],[4,6,11,10]]
> ```

> [!example]- Example 3
> **Input:**
>
> ```python
> `grid` = [[1,2,3],[4,5,6],[7,8,9]], k = 9
> ```
>
> **Output:**
>
> ```python
> [[1,2,3],[4,5,6],[7,8,9]]
> ```

> [!warning]- Constraints
> - `m == grid.length`
>
> 	- `n == grid[i].length`
>
> 	- `1 <= m <= 50`
>
> 	- `1 <= n <= 50`
>
> 	- `-1000 <= grid[i][j] <= 1000`
>
> 	- `0 <= k <= 100`

### Submission:

> [!example]+ Submission
> | Runtime | Memory | Time | Space |
> |---|---|---|---|
> | `11 ms` | `19.7 MB` | `O(m*n)` | `O(1)` |
>
> ```python
> from math import gcd
>
> class Solution:
>     def shiftGrid(self, grid: list[list[int]], k: int) -> list[list[int]]:
>         m, n = len(grid), len(grid[0])
>         s = m * n
>         shift = k % s
>         if shift == 0:
>             return grid
>
>         g = gcd(s, shift)
>         L = s // g
>         for start in range(g):
>             sr, sc = divmod(start, n)
>             pos = start
>             for _ in range(L - 1):
>                 pos = (pos + shift) % s        # jump from previous target, not i + shift
>                 nr, nc = divmod(pos, n)
>                 grid[sr][sc], grid[nr][nc] = grid[nr][nc], grid[sr][sc]
>         return grid
> ```

> [!success]- Reasoning
> 1. Handle k%total==0 case where grid doesn't change due to cyclic nature.
> 2. Use GCD(total_elements, shift) to find number of independent cycles.
> 3. For each cycle starting position, perform L-1 swaps following the rotation pattern.
> 4. Each position maps to (pos+shift)%total after one shift operation.
> 5. In-place rotation by following cycles avoids needing extra O(m*n) space.
>
> **Key insight:** Cycle-based rotation using GCD minimizes redundant swaps, enabling O(1) space.
